Merge master into gh297-apu-4017-writes-reset-and-clock-the-frame-co

Master landed issue #292 ("fix(ppu): expose I/O open bus on write-only
register reads") which independently bumped SaveState.VERSION 10 -> 11
for a PPU open-bus latch byte. My branch also bumped 10 -> 11 for the
deferred $4017 reset pending write (issue #297). To coexist, this merge
bumps the canonical version 11 -> 12 and keeps both v11 (PPU open-bus,
issue #292) and v12 (frame-counter pending write, issue #297) entries
in the SaveState kdoc.

Both subsystems are now uniformly version-aware:

  - PpuAddressedMemory.saveState(out, version) gates the openBus byte
    write on version >= 11, mirroring the existing read-side gate in
    loadState. The previous asymmetric write was a pre-existing bug
    that surfaced when this merge's v5/v6 backwards-compat tests called
    SaveState.save with a low target version; the unconditional write
    produced a v12-format PPU block that a v5/v6 loader couldn't read.
  - Ppu.saveState now forwards its `version` parameter to
    PpuAddressedMemory.saveState (was previously dropped).
  - FrameCounter.saveState / loadState gate the pending-write payload
    on version >= 12 (same logic as before, version bumped).
  - Apu.saveState / loadState forward version to FrameCounter.
  - SaveState.save forwards version to Cpu, Ppu, Apu so callers can
    produce older-format byte streams for migration tests.

The version-aware SaveState.save also unblocks the SaveStateProgressTest
backwards-compat tests for v5 and v6 saves — they previously used a
stripTrailerAndRewriteVersion byte-surgery hack; they now call
SaveState.save directly with the target version, which is cleaner and
no longer fragile to save-format changes.

SaveStateMigrationTest's VERSION assertion and the two new migration
tests are bumped to 12 (v11 -> v12 forward, v11 stays valid because
v11 and v12 differ only in the optional APU pending-write byte).
